Virtual Functions:
------------------
	In C++, run-time polymorphism is achieved through virtual functions. As demonstrated yesterday with a brief introduction.
	
	What is binding in C++?
		When you make a call to a function, which functions is to be called is linked during linking phase of the compilation process.
		
		Linking the function call to its definition is what is referred to binding. 
		
		Remember C++ supports function overloading, so binding determines 
			1. Which function gets called 
			2. When the function call is getting resolved.
		
		For Example:
		-----------
			obj.disp();
			obj.funOne();
				--> Which function gets called depends on the binding type(early or late).
				
		Early Binding:
		--------------
			Function call is resolved at compile time 
		Because it happens at compile time 
			1. Execution is faster
			2. No extra info needed to resolve at run-time
		This is most-widely used
			1. Normal functions 
			2. function overloading
			3. operator overloading
			4. Non-Virtual functions
			5. static functions of a class 
		
		Late Binding:
		-------------
			Function call is resolved at run-time
		Because it happens at run-time, 
			1. Slight delay is resolving at run-time
			2. Extra memory is allocated for stroring extra info which is needed for run-time resolution(VTable (virtual table) and VPtr (virtual Pointer))
			
In C++ implemented using 
	Virtual functions 
=========================================================
	Remember when function overloading is used where you can have multiple functions with same name in same scope (with same class or namespace).
	
	When it comes to virtual functions, we talk about having minimum of two classes where base class and derived class having function with signature. Here two functions in diffent scope. This process is referred to as function overriding in derived class. 
	
	Using base class Pointer, we can call either base class function or derived class function. Since one pointer (pointer of one class) is used to call different functions.  This is run-time polymorphism.

	When It comes to virtual functions:
	-----------------------------------
		In order to implement run-time/late binding, C++ compiler uses a VTable (virtual table) for each polymorphic class(classes having virtual function).
		
		This table is nothing but an array of pointer to functions.
		
		In each object of the class, a pointer is introduced to store  address of the VTable, this pointer is referred to as VPtr(virtual pointer).
		
		Every object of the polymorphic class and its derived classes will have this VPtr. Initialization of this address is the responsibility of the constructor.
		
		i.e., the address of the base class VTable is stored in Base class objects VPtr. 
		Similarly., the address of the derived class VTable is stored in derived class objects VPtr. 
		
		How is Late binding achieved. Let me demonstrate with the help of pointers here.
	=======================================================
	Using virtual functions we achieve late binding. 
		1. Inheritance is involved(minimum of 1 base class and 1 derived class).
		2. Functions in base and derived class should have same signature.
		3. base class function should be made virtual. 
		
	The virtual function in the base class may or may not be overridden in derived class. 
	
	If overridden in derived class, derived class function is called else base class function is called, depending on whether base class pointer or reference variable stores the address of base class object or derived class object.
	
Summary of Internal working of virtual functions:
-------------------------------------------------	
	What is VTable?
		A VTable is a lookup table:
		Created by compiler
		Stores addresses of virtual functions
		Each class with virtual functions has one VTable.

	What is VPtr?
		Each object has a hidden pointer → VPtr
		VPtr points to the class’s VTable

	Call Flow (Runtime):
	--------------------
		Base* b --> object --> vptr --> vtable --> correct function

	Memory Impact:
	--------------
		Each object has 1 extra pointer
		vtable for each class in the hierarchy
		Slight memory overhead for flexibity

Best Practices and Common Pitfalls:	
	Best Practices
		When to Use Virtual Functions. 
		1. One purpose of using inheritance is re-usability of code and second purpose is to achieve polymorphic behaviour.
		
		Here the job of your base class is used as an interface for grouping similar working classes.
		for Example:
			Animal --> Dog, Cat, Bear
			DocumentManager --> txtFile, rtfFile, pdfFile, docFile
			MediaPlayer --> VideoPlayer, AudioPlayer 
			VideoPlayer --> aviPlayer, mp4Player, mkvPlayer
			AudioPlayer --> mp3Player, wavPlayer, aacPlayer
		
		Here, from the above examples base class acts as an interface to group other related classes(derived)
		
		2. Because polymorphic behaviour helps us to organize multiple classes in a hierarchy of classes, this helps to create frameworks(consists of different or multiple classes) or API design.
		
		3. Polymorphism here tries to provide a function in base class which in turn can have different implementation in derived classes. (Actual implementation of the interface can be delayed or later written in derived classes).
		
	Some of the common pitfalls in Polymorphic classes:
	Common Pitfalls:
		1. forgetting to make your destructor virtual
		2. Calling virtual functions inside your constructors
			We assume the object is completely initialized once constructor call is finished. Inside the construct the object is assumed to be uninitialized of partially initialized. You should not expect to perform polymorphic behaviour on partially initialized or uninitialized object.
		3. Use virtual functions only if necessary. If your design requres polymorphic behaviour only then go for it.

Abstract Base Classes
	What Makes a Class Abstract
		A class in C++ is said to be an abstract class if it contains atleast one pure virtual function.
	
	Properties of an Abstract class:
		1. You cannot create objects of such classes but you can create pointers and reference variable.
		2. You can define constructors, destructors
		3. Abstract class is used as a base class whose pointer or reference variable is used for polymorphic behaviour.
		
	Abstract Base classes are used in 
		frameworks, plugin systems and APIs 
		
	Simple API Designing	

		Database --> ABC 
			virtual void connect() = 0;
			virtual void query() = 0;
			virtual void disconnect() = 0;
		
		MySQL: public Database
			overriding the function here 
			
		OracleDB: public Database
			overriding the function here 
			
	Using ABC as interface:
		C++ does not have a keyword interface like Java. We tend to simulate/write a class with no data members and have a pure virtual function 
		
		class VideoPlayer{
		public:
			virtual void play() = 0;
			virtual void rewind() = 0;
			virtual void forward() = 0;
			virtual void stop() = 0;
			virtual VideoPlayer() {}
		};

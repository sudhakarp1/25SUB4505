Templates:
	C++ is said to be a strongly typed language. i.e., to say it differentiates functions with same name with different data types as arguments. 
	
		void fun(int );
		void fun(char );
		void fun(double );
		void fun(float );
--------------------------------------------------------
	When your functions/algorithm is same but the data type is different then you can go for function template.
	
	C++ is said to support different types of programming:
		1. Procedural/function oriented programming
		2. Object Oriented Programming
		3. Generic Programming --> Your focus is on solving problems rather than the data type. Here we dont bother what kind of data type is used.
		
	C++ support/implementation of generic programming is through templates.
		Template is the syntax used in C++ for implementing generic programming.
-----------------------------------------------------------
	Templates allow you to write generic code that works on any data type.
		"Write once , use for many types"
	
	Advantages of templates:
	------------------------
		Code Reusability and Efficiency:
		--------------------------------
			1. One function/class works for many types 
			2. Eliminates duplicate code  (You dont need to copy paste the same code for different data types)
			
			3. Compiler internally generates code for specific data type depending on the argument passed.
				if you are passing int --> fun (int ) is generated at compile time 
			Because all these are done during compile time no run-time overhead and it is faster that the polymorphism(virtual function calls)
-----------------------------------------------------
	Type safety & Flexibility:
	-------------------------
		Any errors are generated at compile time 
		Since separate copies are generated at compile time strong typed nature of C++ is maintained.
		
	Function Templates:
	-------------------
		Applying the templates on function:
		
		syntax:
			template<typename T>
			return_type funcName(arguments){
			
			}
			
		for Example:
			template<typename T>
			T Add(T x, T y){
				return x+y;
			}
			
	Function template with multiple argument:
	-----------------------------------------
	template <typename DT, typename DU>
	void fun(DT varOne, DU varTwo){
		cout<<"varOne: "<<varOne<<"\tvarTwo: "<<varTwo<<endl;
	}
	
	Function template overloading:
	-----------------------------
		Just like normal functions function template can be overloaded based on number of arguments 
		
	Template Specialization(function):
	---------------------------------
		When you want to implementation for a specific type.
	
	Class Template:
	---------------
		Applying the template syntax on classes to create generic classes. 
		
		template<typename T>
		class className{
			T data;
		public:
			//functions here
		};

Smart pointers:
---------------
	We did discuss on pointers some time back, and we solved some classes with dynamic memory allocation 
	
	
	int *iPtr = new int[10];
		//raw pointer --> Usage of pointers directly 
		
	From the programmers point of view:
		Programmer must take care of these issues that might arise when using pointers with dynamic memory allocation.
		
		1. memory leak:
		
			int *iPtr = new int[100];
				//memory is allocated here.
				
			int var = 10;
			
			iPtr = &var; //assigning new address
			
			//there is a memory leak 
			delete iPtr;
------------------------------------------------
		int main(){
			int iVar = 10;
			//perform task here using iVar
			//cout<<"IVar: "<<iVar<<endl; //
			iVar = 20;
			cout<<"IVar: "<<iVar<<endl; //
		}

	2. Dangling Pointer
		Pointer holding the address of the deleted memory.
		
		Two or more pointers pointing to the same location. When one object goes out of scope, the pointer in the other objects becomes a dangling pointer. (We did discuss this in shallow copy of objects) 
	
	3. Double deletion
		Because of dangling pointer due to shallow copy.
		
	4. Exception Unsafe code
		During unwinding of stack, destructors of local objects are called. 
		When destructors for heap based objects are not called, resulting in memory leakage.

In order to handle the above mentioned issues:
	Smart pointer classes are introduced to handle these issues as part of the standard library.
===========================================================	
	Smart Pointers are template classes provided in the standard library(Modern C++) that 
		1. Automatically manage dynamic allocated memory 
		2. Delete memory when object goes out of scope 
		3. RAII (Resource Acquisition Is Initialization)
			The job of this class is to provide wrapping around a pointer where the pointer and its memory allocation is not exposed directly to the exception code(the code that might arise exception).
			
			Yesterday I introduced a class Pointer with Test class pointer.
==========================================================
	Why do we use smart pointers?
		1. Automatic memory management 
		2. Exception safety
		3. Clear ownership semantics
		4. Prevent memory leaks 
		5. Part of Modern C++.

	What is ownership semantics?
		1. Pointer is a variable which stores address of another variable. 
		
		Dynamically allocated memory in the heap is treated as a resource.
		
		At any given point of time if one pointer points(stores) to the heap memory, then the ownership is exclusive. 
		
		If two or more pointers pointing to the same location in heap then it is shared ownership.
		
		What is tranfering ownership?
			iPtr = new int[100];
			//storing the data into the location
			
			iPtrOne = iPtr; 
			//address is copied here 
			//now two pointers iPtrOne and iPtr are storing the same address.
			
			iPtr = nullptr; 
				//iPtr variable is now pointing to null or giving up the ownership to iPtrOne variable.
			
=============================================================
In modern C++:
	These are the classes provided as part of smart pointer. 
	
	unique_ptr --> Exclusive ownership, cannot be copied , but can be moved (cut and paste not copy and paste).
	
	shared_ptr --> Shared ownership, multiple owners, internally uses reference counter to keep track of number of owners. Resource is deleted only when this reference count becomes 0(no more owners left). 
	
	weak_ptr --> 
		--> as part of non-owning reference to shared_ptr. 
		It does not increase reference count 
		used to avoid circular dependency.
====================================================
	What is circular/Cyclic Dependency:
		class A 
			shared_ptr<B> b;
		
		class B 
			shared_ptr<A> a;		
======================================================

There was a simple smart pointer class auto_ptr introduced in traditional C++ (C++98) which was deprecated in C++11 and later(C++17) version completely removed.
	Because of unsafe-ownership transfer semantics.
	
	auto_ptr<int> ptrOne(new int(100));
	auto_ptr<int> ptrTwo = ptrOne; 
	
		This was introduced in C++98, where move semantics were not introduced. Where as when compared with unique_ptr, copying is not allowed but moving was allowed.

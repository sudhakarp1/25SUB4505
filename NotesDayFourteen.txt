	Condition Variables		
	-------------------
	
	A Condition variable is a synchronization mechanism that allows:
		One or more threads to wait until a specific condition becomes true.
		Other threads to notify the waiting threads when the condition changes.
		
			<condition_variable>
			
			condition_variable obj;
	In the example code given:
-------------------------------------		
		Step-by-Step Execution
			funOne thread acquires mutex
			ready == false → funOne thread sleeps
			Main thread sets ready = true
			notify_one() wakes funOne thread
			funOne thread rechecks condition
			funOne thread proceeds
-------------------------------------------------------
	notify_all() --> wakes all waiting threads

	Futures and Promises in C++ (Modern)
	------------------------------------
		Futures and promises are synchronization mechanism that allow:
			one thread to produce a value(result) or an exception.
			Another thread to consume(use) the value later.
		
		This mechanism enables one-time communication between threads.
		Classes involved:
			promise<T> 		Set(produces) a value 
			future<T> 		Get(consumes) a value 
			
		This is the explanation of the code given:
			Step-by-Step Execution
				Main creates promise
				Main obtains future
				Promise passed to child(calculateSum) thread
				Child(calculateSum) computes result
				Child((calculateSum)) calls set_value()
				future.get() unblocks
				Value is returned	
============================================================
Shared Futures:
	A normal future can be consumed only once.

	To allow multiple consumers:
		shared_future<int> sf = f.share();

	Example use case:
		Multiple threads waiting for same configuration data

	Thread Pools:
	-------------
		A thread pool is a concurrency design pattern where:
		1. create a fixed number of child/worker threads 
		2. Tasks are assigned/submitted to a queue 
		3. Worker threads reuse themselves to execute tasks
		4. Threads are not created and destroyed for each task.
		
	A class for implementing the above idea with the concepts we discussed thus far can be applied.

	A SimpleThreadPool{}; //this will not handle return values

	<functional>
	function<funPointer>
	
	function<> is a general purpose polymorphic wrapper that can store and invoke(call) any callable object with a given signature.
	
	In C++, for callable objects 
		1. normal function address
		2. Lambda expression 
		3. Functors 
		4. Member functions 
		5. functors or callable objects from standard library

	We have already discussed on function pointers(Pointer to functions) in details
	
	Here we are looking at an alternative:
	
	int Add(int x, int y){
		return x + y;
	}
	int Sub(int x, int y){
		return x - y;
	}	
	
	function<int (int, int)> fObj = Add;		
	int res = fObj(100, 200);
	
or using Lambda expression
	fuction<int (int,int)> fObj = [](int x, int y){
										return x + y;
									};
		int res = fObj(10, 20);

Most commonly used options:
---------------------------
	-o   Output executable file 
		gcc -o first first.c 
		g++ -o first first.cpp 

	-Wall 	--> Enable all warnings 
	-Wextra --> Extra warnings 
	-std=c++17 --> Use C++17 standard
	-c 		--> Compilation only 
	-g 		--> Debug info (Compilation)
	-I dir  --> Additional Include Directory
	-L dir  --> Additional Link(Library) Directory
	-l pthread --> Link Library name 

For Example:	
	g++ -Wall -Wextra -std=c++17 main.cpp -o app.exe 	
	
Some options used in optimization:
----------------------------------
	-O0 	--> No optimization (usually in debug)
	-O1 	--> Basic optimization
	-O2 	--> Recommended optimization
	-O3 	--> Aggressive optimization
	-Os 	--> optimization for size
